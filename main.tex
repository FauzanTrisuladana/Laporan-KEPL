Jika pada penugasan sebelumnya \textit{image container} dibangun menggunakan pendekatan \textit{single-stage build} berbasis Debian, maka pada penugasan ini dilakukan restrukturisasi menyeluruh mencakup pemisahan tahap kompilasi dan penyajian (\textit{multi-stage build}), penguncian versi (\textit{version pinning}) menggunakan varian minimalis Alpine Linux, penerapan hak akses pengguna \textit{non-root} (\texttt{USER www-data}), konfigurasi pemantauan kesehatan (\texttt{HEALTHCHECK}), serta otomasi penerbitan \textit{image} ke GitHub Container Registry (GHCR) melalui GitHub Actions.

\par Metadata repositori dan tautan artefak publikasi praktikum diuraikan sebagai berikut:
\begin{itemize}[leftmargin=*]

\subsection{Refaktorisasi Dockerfile Menjadi Arsitektur Multi-Stage Build}

\par Pada arsitektur konvensional \textit{single-stage build}, seluruh perkakas pengembangan (\textit{build tools}), pustaka kompilasi, dependensi Composer, serta kode sumber disatukan ke dalam satu \textit{layer} akhir yang sama. Hal ini menyebabkan pembengkakan ukuran \textit{image} dan memperluas bidang serangan (\textit{attack surface}) di lingkungan produksi. Untuk mengatasi kelemahan tersebut, berkas \texttt{Dockerfile} direfaktorisasi menggunakan pola \textit{multi-stage build} yang memisahkan proses menjadi dua tahap terisolasi: tahap pembangun (\textit{builder stage}) dan tahap pelayan runtime (\textit{runner stage}). Konfigurasi lengkap \texttt{Dockerfile} hasil optimasi disajikan pada Kode \ref{lst:dockerfile}.

\lstinputlisting[language=dockerfile, caption={[Konfigurasi Dockerfile Multi-Stage]{Berkas Konfigurasi \texttt{Dockerfile} dengan Arsitektur Multi-Stage Build, Varian Alpine, User Non-Root, dan Healthcheck}}, label={lst:dockerfile}]{resource/Code/Dockerfile}

\par Berdasarkan Kode \ref{lst:dockerfile}, arsitektur berkas \texttt{Dockerfile} disusun secara modular dengan rincian teknis sebagai berikut:
\begin{enumerate}[leftmargin=*]
  \item \textbf{Tahap 1: Builder (\texttt{AS builder})}:\\
        Instruksi baris 5 menetapkan \textit{base image} pembangun menggunakan distribusi:\\
        \texttt{dunglas/frankenphp:1-php8.4-alpine}.\\
        Pada baris 8, biner Composer versi 2 disalin langsung dari \textit{image} resmi \texttt{composer:2} melalui instruksi\\
        \texttt{COPY --from=composer:2 /usr/bin/composer /usr/bin/composer}.\\
        Setelah direktori kerja \texttt{/app} ditetapkan,\\
        berkas manifes dependensi \texttt{composer.json} dan \texttt{composer.lock} disalin terlebih dahulu (baris 13) sebelum kode aplikasi disalin. Perintah \texttt{composer install} dijalankan pada baris 16--22 dengan parameter produksi yang ketat:
        \begin{itemize}[leftmargin=*]
          \item \texttt{--no-dev}: Mengabaikan instalasi seluruh dependensi pengembangan (seperti PHPUnit, Mockery, Collision, Faker).
          \item \texttt{--no-interaction}: Menonaktifkan interaksi prompt terminal.
          \item \texttt{--no-plugins} dan \texttt{--no-scripts}: Mencegah eksekusi skrip otomatis yang tidak diperlukan pada tahap awal penyusunan dependensi.
          \item \texttt{--prefer-dist} dan \texttt{--no-autoloader}: Mengunduh arsip distribusi dependensi secara cepat tanpa menghasilkan peta \textit{classmap} terlebih dahulu.
        \end{itemize}
        Selanjutnya, baris 25 menyalin seluruh kode sumber aplikasi ke direktori pembangun, disusul pembersihan berkas \textit{cache} sementara dan eksekusi perintah optimasi \textit{autoloader}:\\
        \texttt{composer dump-autoload --optimize --no-dev --no-scripts}\\
        pada baris 28--29 guna menghasilkan berkas \textit{classmap} teroptimasi secara statis.
  \item \textbf{Tahap 2: Runner (\texttt{AS runner})}:\\
        Instruksi baris 37 mendeklarasikan awal tahap runtime baru yang sepenuhnya bersih, kembali menggunakan \textit{base image} \texttt{dunglas/frankenphp:1-php8.4-alpine}. Biner Composer beserta perkakas pembangun tidak diikutsertakan. Pada baris 40--47, modul inti PHP esensial dipasang untuk melayani \textit{request}, yaitu \texttt{pdo\_mysql}, \texttt{gd}, \texttt{intl}, \texttt{zip}, \texttt{bcmath}, \texttt{opcache}, dan \texttt{curl}.
  \item \textbf{Penyalinan Artefak Bersih (\texttt{COPY --from=builder})}:\\
        Kunci utama efisiensi arsitektur ini terletak pada instruksi baris 52, yaitu\\
        \texttt{COPY --from=builder /app /app}.\\
        Instruksi ini secara selektif hanya menyalin direktori kerja aplikasi yang telah memuat direktori \texttt{vendor} bersih dan kode sumber teroptimasi dari tahap pembangun, tanpa menyertakan artefak kompilasi eksternal maupun biner Composer.
  \item \textbf{Penguncian Versi dan Pemilihan Varian Minimalis}:\\
        Alih-alih menggunakan tag generik \texttt{latest} yang tidak deterministik atau varian berbasis Debian glibc yang berbobot besar, konfigurasi ini secara konsisten mengunci versi rilis pada tag spesifik\\
        \texttt{dunglas/frankenphp:1-php8.4-alpine}.\\
        Distribusi Alpine Linux menggunakan pustaka C yang sangat ramping (\textit{musl libc}) dan pengelola paket \texttt{apk}, sehingga fondasi sistem operasi kontainer menjadi sangat minimalis.
\end{enumerate}

\subsection{Pengerasan Keamanan Non-Root User dan Monitoring Healthcheck}

\par Standar keamanan industri kontainer mewajibkan penerapan prinsip \textit{Principle of Least Privilege}. Secara bawaan, apabila tidak ditentukan lain, proses di dalam kontainer akan dieksekusi dengan hak istimewa pengguna tertinggi (\texttt{root} dengan UID 0). Kondisi ini sangat berbahaya karena jika terjadi eksploitasi kerentanan keamanan pada aplikasi web (misalnya eksekusi kode berbahaya secara jarak jauh), penyerang berpotensi memperoleh kendali penuh atas sistem kontainer bahkan melakukan pelarian kontainer (\textit{container breakout}) ke mesin \textit{host}.

\par Untuk memitigasi risiko tersebut, pada tahap \textit{runner} berkas \texttt{Dockerfile} disematkan instruksi hak akses dan penetapan pengguna \textit{non-root}:
\begin{lstlisting}[language=dockerfile, caption={[Konfigurasi Hak Akses dan User Non-Root]{Pengaturan Perizinan Direktori dan Instruksi \texttt{USER www-data}}}, label={lst:user-non-root}]
RUN mkdir -p /data/caddy /config/caddy /app/storage /app/bootstrap/cache \
    && rm -f /app/bootstrap/cache/*.php \
    && chown -R www-data:www-data /data/caddy /config/caddy /app/storage /app/bootstrap/cache \
    && chmod -R 775 /app/storage /app/bootstrap/cache

USER www-data
\end{lstlisting}

\par Berdasarkan Kode \ref{lst:user-non-root}, sebelum instruksi \texttt{USER www-data} diaktifkan, direktori kerja Caddy dan direktori aplikasi Laravel yang memerlukan izin tulis (\texttt{storage} untuk berkas log dan sesi, serta \texttt{bootstrap/cache} untuk tembolok rute dan konfigurasi) diserahkan kepemilikannya kepada pengguna dan grup sistem \texttt{www-data:www-data} dengan mode izin \texttt{775}. Setelah izin dipersiapkan, instruksi \texttt{USER www-data} dideklarasikan sehingga seluruh proses runtime FrankenPHP berjalan di bawah konteks pengguna non-istimewa.

\subsection{Otomasi Pipeline CI/CD dan Publikasi Image ke GitHub Container Registry (GHCR)}

\par Tahap akhir penugasan adalah mengintegrasikan berkas \texttt{Dockerfile} ke dalam alur kerja integrasi dan pengiriman berkelanjutan (\textit{Continuous Integration and Continuous Deployment} / CI/CD) menggunakan GitHub Actions. Tujuannya adalah mengotomasi proses kompilasi \textit{image} setiap kali terjadi pembaruan kode, serta mempublikasikan \textit{image} yang siap produksi ke registri kontainer resmi GitHub (\textit{GitHub Container Registry} / GHCR pada domain \texttt{ghcr.io}).

\par Sebelum mengeksekusi \textit{workflow}, konfigurasi hak akses keamanan repositori wajib disesuaikan agar token bawaan \texttt{GITHUB\_TOKEN} diizinkan menulis dan memperbarui paket pada registri GHCR. Konfigurasi perizinan repositori tersebut ditunjukkan pada Gambar \ref{fig:konfigurasi-github-actions-permissions}.

\end{figure}

\par Berdasarkan Gambar \ref{fig:konfigurasi-github-actions-permissions}, pada menu \textit{Settings} $\rightarrow$ \textit{Actions} $\rightarrow$ \textit{General} bagian \textit{Workflow permissions}, opsi perizinan ditetapkan ke \textbf{\textit{Read and write permissions}}. \par Berdasarkan Kode \ref{lst:docker-publish}, alur kerja otomasi dirancang dengan memperhatikan kaidah rekayasa perangkat lunak modern sebagai berikut:
\begin{enumerate}[leftmargin=*]
  \item \textbf{Pemicu Eksekusi (\textit{Triggers})}:\\
        Baris 3--7 mengonfigurasi pemicu \textit{workflow} secara otomatis pada peristiwa \texttt{push} ke cabang \texttt{main}, \texttt{dev}, serta cabang fitur (\texttt{feature/**}) dan cabang pemeliharaan (\texttt{chore/**}), serta pada peristiwa \texttt{pull\_request} menuju cabang \texttt{main}.
  \item \textbf{Normalisasi Nama Image Menjadi Huruf Kecil (\textit{Lowercase Normalization})}:\\
        Registri GHCR menerapkan aturan ketat bahwa nama paket dan organisasi wajib menggunakan huruf kecil semua (\textit{lowercase}). Baris 24--30 mengatasi potensi kegagalan akibat nama pengguna berhuruf kapital melalui perintah transformasi:
        \begin{center}
          \texttt{\footnotesize OWNER\_LOWER=\$(echo "\$\{\{ github.repository\_owner \}\}" | tr '[:upper:]' '[:lower:]')}
        \end{center}
        sehingga variabel \texttt{IMAGE\_NAME} terbentuk secara valid menjadi\\
        \texttt{ghcr.io/fauzantrisuladana/evolusi-laravel-app}.
  \item \textbf{Otentikasi Mandiri Aman}:\\
        Baris 32--38 memanfaatkan tindakan resmi \texttt{docker/login-action@v3} untuk masuk ke registri \texttt{ghcr.io} menggunakan token internal \texttt{\$\{\{ secrets.GITHUB\_TOKEN \}\}}, sehingga tidak memerlukan pembuatan token akses personal (\textit{Personal Access Token} / PAT) manual yang rentan bocor.
  \item \textbf{Skema Penandaan Deterministik (\textit{Deterministic Tagging})}:\\
        Baris 42--52 memanfaatkan tindakan \texttt{docker/metadata-action@v5} untuk mengekstrak tag. Sesuai instruksi soal, penandaan tidak hanya bergantung pada tag \texttt{latest}, melainkan menyematkan nomor \textit{commit} SHA panjang secara deterministik (\texttt{type=sha,format=long,prefix=}) yang menghasilkan tag unik berbasis \texttt{\$\{\{ github.sha \}\}}.
  \item \textbf{Kompilasi dan Pengiriman (\textit{Build and Push})}:\\
        Baris 54--61 mengeksekusi \texttt{docker/build-push-action@v6} dengan parameter \texttt{push: true} untuk mengompilasi berkas \texttt{Dockerfile} dan mengirimkan \textit{layer image} beserta seluruh tag ke GHCR.
\end{enumerate}

\section{Kesimpulan}

\par Berdasarkan rangkaian refaktorisasi arsitektur, pengujian kuantitatif empiris, pengerasan konfigurasi keamanan, dan otomasi alur kerja pengiriman yang telah dilaksanakan pada praktikum Tugas \Pertemuan, diperoleh kesimpulan sebagai berikut:
\begin{enumerate}[leftmargin=*]
  \item \textbf{Keberhasilan Reduksi Ukuran Image Melalui Multi-Stage Build}:\\
        Penerapan arsitektur \textit{multi-stage build} yang memisahkan tahap pembangunan (\textit{builder}) dan tahap penyajian (\textit{runner}), dikombinasikan dengan penguncian versi pada distribusi minimalis\\
        \texttt{dunglas/frankenphp:1-php8.4-alpine},\\
        terbukti secara empiris berhasil memangkas ukuran \textit{image} dari 725 MB menjadi 296 MB. Pengurangan sebesar 429 MB ini menghasilkan efisiensi penurunan ukuran sebesar 59,17\%, mempercepat waktu transfer jaringan dan menghemat alokasi ruang penyimpanan server.
  \item \textbf{Pengerasan Keamanan Kontainer Menggunakan User Non-Root}:\\
        Pengalihan konteks eksekusi dari akun \texttt{root} ke akun sistem \texttt{www-data} berhasil memenuhi prinsip \textit{Principle of Least Privilege}. Pengujian verifikasi identitas menggunakan perintah terminal \texttt{podman exec whoami} menghasilkan luaran \texttt{www-data}, membuktikan bahwa kontainer terlindungi dari ancaman penyalahgunaan hak akses istimewa sistem operasi.
  \item \textbf{Peningkatan Keandalan Layanan Berbasis Healthcheck}:\\
        Instruksi \texttt{HEALTHCHECK} pada berkas \texttt{Dockerfile} menyediakan mekanisme pemantauan kesehatan periodik atas rute aplikasi Laravel. Kontainer berjalan stabil dan menyajikan antarmuka web pada pemetaan port 8007.
  \item \textbf{Otomasi Alur Rilis CI/CD dan Publikasi Mandiri ke GHCR}:\\
        Implementasi \textit{pipeline} GitHub Actions berhasil mengotomasi proses kompilasi dan distribusi \textit{image} ke GitHub Container Registry (\texttt{ghcr.io}) secara mandiri menggunakan \texttt{GITHUB\_TOKEN}. Skema penandaan berbasis nomor \textit{commit} SHA penuh menjamin sifat ketertelusuran (\textit{traceability}) dan keterulangan (\textit{reproducibility}) rilis, serta perubahan visibilitas paket menjadi \textit{Public} memungkinkan aksesibilitas pengunduhan kontainer secara terbuka dan terstandarisasi.
\end{enumerate}
