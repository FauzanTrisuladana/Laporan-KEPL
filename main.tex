\subsection{Pengembangan Aplikasi Web Sederhana (Laravel)}

\par Repositori ini memuat aplikasi web fungsional yang dibangun di atas kerangka kerja (\textit{framework}) Laravel 11 dengan bahasa pemrograman PHP versi 8.4. Aplikasi yang dikembangkan dirancang sebagai modul URL Shortener sederhana yang dilengkapi dengan sistem autentikasi pengguna (\textit{Login} dan \textit{Register}), manajemen pembuatan dan pengalihan tautan singkat (\textit{links}), serta pencatatan analitik pengunjung (\textit{visitors}).

\par Pada aspek arsitektur perangkat lunak, sistem mengimplementasikan pola desain \textit{Model-View-Controller} (MVC). Struktur basis data dikelola melalui skema migrasi tabel (\textit{database migrations}) yang terhubung dengan model Eloquent: \texttt{User} untuk menyimpan kredensial pengguna, \texttt{Link} untuk menyimpan relasi URL asli dengan kode tautan pendek, serta \texttt{Visitor} untuk mencatat metadata alamat IP, peramban (\textit{user agent}), dan waktu akses pengunjung. Seluruh logika autentikasi dikendalikan oleh \texttt{AuthController} yang terintegrasi dengan berkas perutean \texttt{routes/web.php} serta tampilan antarmuka Blade modern yang responsif dengan dukungan tema gelap (\textit{dark theme}).

\subsection{Penerapan Mutu Pesan Commit (Conventional Commits)}

\par Dalam disiplin rekayasa perangkat lunak modern, kejelasan catatan riwayat perubahan (\textit{commit history}) merupakan cerminan profesionalisme dan keteraturan pengembang. Berdasarkan kriteria penugasan praktikum, penulisan pesan commit wajib mematuhi spesifikasi standar \textit{Conventional Commits} dengan format baku:
\begin{center}
  \texttt{<type>(<scope>): <subject>}
\end{center}
Pesan commit yang tidak bermakna seperti "update", "fix bug", atau deskripsi ambigu lainnya dihindari sepenuhnya. Penerapan konvensi ini memberikan manfaat penting dalam mempermudah peninjauan kode sumber (\textit{code review}), melacak riwayat perubahan secara kronologis, memfasilitasi pelacakan regresi kode (\textit{git bisect}), serta memungkinkan pembuatan catatan rilis (\textit{changelog}) secara otomatis.

\par Pada repositori ini, seluruh commit telah mengimplementasikan konvensi semantik tersebut secara konsisten. Rincian riwayat commit yang tercatat di dalam repositori diuraikan sebagai berikut:
\begin{itemize}
  \item \texttt{4059021 - feat(project)}: Inisialisasi awal struktur repositori proyek, pengaturan lisensi sumber terbuka, dan pembuatan dokumentasi awal pada berkas \texttt{README.md}.
  \item \texttt{037c383 - feat(project)}: Instalasi kerangka kerja Laravel 11 beserta dependensi pustaka inti PHP versi 8.4 ke dalam direktori kerja proyek.
  \item \texttt{f6042bf - feat(workflow)}: Pembuatan dan penambahan berkas konfigurasi otomasi CI (\texttt{.github/workflows/ci.yml}) untuk pengujian unit dan linting kode otomatis.
  \item \texttt{24fa6c1 - fix(ci state)}: Penyesuaian aturan pemicu (\textit{triggers}) pada berkas CI agar merespons aktivitas \textit{push} dan \textit{pull request} pada cabang \texttt{main}, \texttt{dev}, serta cabang fitur (\texttt{feature/**}).
  \item \texttt{d455005 - feat(migration, model)}: Penambahan skema migrasi tabel basis data (\textit{users}, \textit{links}, \textit{visitors}), pendefinisian relasi model Eloquent, serta penyesuaian dependensi workflow CI.
  \item \texttt{b323f91 - fix(migration, model)}: Perbaikan tata format impor pustaka dan penyesuaian gaya penulisan kode pada migrasi dan model agar mematuhi standar linter Laravel Pint.
  \item \texttt{f1b78e5 - feat(login)}: Implementasi fitur autentikasi secara komprehensif, meliputi pengendali \texttt{AuthController}, konfigurasi perutean web pada \texttt{routes/web.php}, serta tampilan antarmuka Blade untuk halaman login dan registrasi.
\end{itemize}
\par Riwayat commit di atas membuktikan bahwa setiap commit mewakili satu unit perubahan fungsional yang teratomisasi (\textit{atomic commit}), sehingga evolusi kode sumber terdokumentasi secara transparan dan teratur.

\subsection{Alur Percabangan (Branching Workflow) dan Pull Request}

\par Strategi manajemen percabangan yang diterapkan pada repositori ini mengadopsi variasi standar industri \textit{Git Flow} dengan struktur tiga tingkatan hierarki cabang:
\begin{enumerate}[label=\arabic*.]
  \item \textbf{Cabang Produksi (\texttt{main})}: Berfungsi sebagai cabang rilis utama yang hanya memuat kode yang telah teruji secara penuh, stabil, dan siap dijalankan di lingkungan produksi. Segala bentuk \textit{push} langsung (\textit{direct push}) ke cabang ini dilarang keras melalui aturan proteksi cabang (\textit{branch protection}).
  \item \textbf{Cabang Pengembangan (\texttt{dev})}: Berfungsi sebagai cabang integrasi aktif tempat fitur-fitur baru digabungkan dan diuji secara komparatif sebelum dinyatakan siap dirilis ke cabang \texttt{main}.
  \item \textbf{Cabang Fitur (\texttt{feature/ci})}: Dibuat sebagai turunan dari cabang \texttt{dev} untuk mengerjakan fitur otomasi CI secara terisolasi tanpa mengganggu stabilitas basis kode yang sedang aktif dikembangkan.
\end{enumerate}

\par Sesuai dengan batasan instruksi tugas, penggabungan kode dari cabang fitur hingga mencapai cabang utama wajib melalui dua tahapan Pull Request (PR):
\begin{itemize}
  \item \textbf{Pull Request \#1 (\texttt{feature/ci} $\rightarrow$ \texttt{dev})}: Bertujuan meninjau dan mengintegrasikan konfigurasi alur kerja CI awal dari cabang fitur ke dalam cabang pengembangan \texttt{dev}.
  \item \textbf{Pull Request \#2 (\texttt{dev} $\rightarrow$ \texttt{main})}: Bertujuan menggabungkan seluruh hasil pengembangan aplikasi yang telah stabil dari cabang \texttt{dev} menuju cabang produksi \texttt{main} sebagai rilis awal tugas.
\end{itemize}

\subsection{Konfigurasi Continuous Integration (CI) dan Analisis Log Workflow}

\par Untuk menjamin kualitas mutu perangkat lunak serta mencegah masuknya kode yang rusak atau tidak terstandarisasi ke dalam cabang utama, repositori diintegrasikan dengan sistem \textit{Continuous Integration} (CI) berbasis GitHub Actions. Konfigurasi otomasi didefinisikan pada berkas \texttt{.github/workflows/ci.yml} sebagaimana disajikan pada Kode \ref{lst:ci-workflow}.

\begin{lstlisting}[language=yaml, caption={Konfigurasi Otomasi CI GitHub Actions (\texttt{.github/workflows/ci.yml})}, label={lst:ci-workflow}]
name: CI

on:
  push:
    branches: ['main', 'dev', 'feature/**']
  pull_request:
    branches: ['main', 'dev']

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.4'
      - run: composer install --no-progress --no-interaction
      - run: cp .env.example .env
      - run: php artisan key:generate
      - run: php artisan migrate --seed
      - run: php artisan test

  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.4'
      - run: composer install --no-progress --no-interaction
      - run: vendor/bin/pint --test
\end{lstlisting}

\par Berdasarkan sintaks pada Kode \ref{lst:ci-workflow}, berikut adalah penjelasan dari eksekusi kode per barisnya:
\begin{itemize}
  \item \texttt{name: CI}: Menetapkan label penamaan alur kerja otomasi integrasi berkelanjutan sebagai "CI".
  \item \texttt{on: push: branches: ...} dan \texttt{pull\_request: ...}: Mendefinisikan aturan pemicu (\textit{triggers}) otomatis yang akan mengaktifkan workflow setiap kali terjadi peristiwa \textit{push} ke cabang \texttt{main}, \texttt{dev}, atau cabang fitur (\texttt{feature/**}), serta saat pembukaan \textit{pull request} ke cabang \texttt{main} dan \texttt{dev}.
  \item \texttt{jobs: test}: Mendefinisikan tugas (\textit{job}) pengujian fungsional aplikasi pada lingkungan virtual \texttt{ubuntu-latest}.
  \item \texttt{actions/checkout@v4}: Mengunduh dan menyalin kode sumber repositori ke dalam mesin virtual runner GitHub.
  \item \texttt{setup-php@v2} (PHP 8.4): Mempersiapkan lingkungan eksekusi PHP versi 8.4 beserta ekstensi yang dipersyaratkan oleh Laravel.
  \item \texttt{composer install}: Mengunduh dan menginstal seluruh pustaka dependensi PHP yang terdaftar pada \texttt{composer.json} secara otomatis tanpa prompt interaktif.
  \item \texttt{cp .env.example .env}: Menyalin template konfigurasi variabel lingkungan untuk pengujian CI.
  \item \texttt{php artisan key:generate}: Membuat kunci enkripsi aplikasi unik pada berkas konfigurasi \texttt{.env}.
  \item \texttt{php artisan migrate --seed}: Mengeksekusi migrasi skema tabel ke basis data SQLite virtual dan mengisi data awal (\textit{seeding}).
  \item \texttt{php artisan test}: Menjalankan seluruh pengujian unit dan fitur bawaan Laravel untuk memverifikasi fungsionalitas aplikasi.
  \item \texttt{jobs: lint}: Mendefinisikan tugas kedua yang berfokus pada verifikasi kerapian dan kepatuhan gaya penulisan kode sumber (\textit{code style}).
  \item \texttt{vendor/bin/pint --test}: Menjalankan perkakas linter Laravel Pint dalam mode pengujian (\texttt{--test}) untuk memastikan seluruh berkas PHP mematuhi standar PSR-12 dan konvensi resmi Laravel.
\end{itemize}

\subsection{Kerapian Repositori dan Keamanan Kode (Repository Hygiene)}

\par Selain aspek fungsionalitas dan otomasi pengujian, kerapian repositori dikelola secara disiplin untuk mencegah kebocoran informasi kredensial serta menjaga kebersihan repositori:
\begin{itemize}
  \item \textbf{Pencegahan Kebocoran Kredensial}: Berkas konfigurasi \texttt{.gitignore} diatur secara ketat untuk mengabaikan berkas-berkas sensitif seperti berkas lingkungan \texttt{.env}, berkas cadangan (\texttt{.env.backup}), berkas kunci sesi dan enkripsi (\texttt{storage/*.key}), berkas basis data SQLite lokal, serta direktori dependensi eksternal (\texttt{vendor/} dan \texttt{node\_modules/}). Penerapan ini mencegah kebocoran kredensial rahasia ke publik yang dapat dieksploitasi oleh pihak luar.
  \item \textbf{Dokumentasi Repositori (\texttt{README.md})}: Berkas \texttt{README.md} disusun secara informatif dan komprehensif, memuat identitas pengembang, deskripsi singkat modul aplikasi, prasyarat sistem (PHP 8.4 dan Composer), panduan instalasi langkah demi langkah, instruksi konfigurasi basis data dan migrasi, serta perintah menjalankan unit test dan linter lokal.
\end{itemize}

\end{enumerate}
