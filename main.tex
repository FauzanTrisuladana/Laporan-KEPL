\par Praktikum Konstruksi dan Evolusi Perangkat Lunak Tugas \Pertemuan\ melanjutkan pengembangan repositori proyek\\

\par Metadata repositori beserta struktur lingkungan kerja diuraikan sebagai berikut:
\begin{itemize}[leftmargin=*]
  \item \textbf{Organisasi GitHub}: KEPL2026\\
        {\footnotesize\url{https://github.com/KEPL2026}}
  \item \textbf{Repositori Proyek}: \texttt{evolusi-pl-24-538699-SV-24524}\\
        {\footnotesize\url{https://github.com/KEPL2026/evolusi-pl-24-538699-SV-24524}}
  \item \textbf{\textit{Branch} \texttt{main}}: \textit{Branch} produksi stabil yang menjadi target akhir rilis dan satu-satunya \textit{branch} yang diizinkan menjalankan \textit{job deployment}.
  \item \textbf{\textit{Branch} \texttt{dev}}: \textit{Branch} integrasi perantara sebelum seluruh perubahan digabungkan ke \textit{branch} utama.
  \item \textbf{\textit{Feature Branch} (\texttt{feature/vue} dan \texttt{feature/api})}: \textit{Branch} pengerjaan isolasi fungsionalitas modul REST API Laravel dan pengembangan antarmuka Vue 3.

\end{itemize}

\subsection{Penyediaan Endpoint REST API pada Backend Laravel}

\par Memenuhi butir penugasan pertama, lapisan \textit{backend} Laravel dikembangkan untuk menyediakan \textit{endpoint} JSON dari tabel CRUD yang telah dibuat pada pertemuan sebelumnya, yaitu tabel \texttt{links} yang berfungsi sebagai sistem URL Shortener. \textit{Endpoint} ini dirancang mengikuti kaidah arsitektur RESTful yang rapi dengan pemanfaatan \textit{Resource Routing} dan pemisahan lapisan transformasi data.

\subsubsection{Konfigurasi Routing dan Controller API}
\par Definisi \textit{route} antarmuka data diatur pada berkas \texttt{routes/api.php} menggunakan kelompok penamaan \textit{route} \texttt{api.} sebagaimana ditunjukkan pada Kode \ref{lst:routes-api}.

\begin{lstlisting}[language=php, caption={[Definisi Endpoint REST API]{Definisi Endpoint REST API pada \texttt{routes/api.php}}}, label={lst:routes-api}]
<?php

use App\Http\Controllers\Api\LinkController;
use Illuminate\Support\Facades\Route;

Route::name('api.')->group(function () {
    Route::get('/links/stats/count', [LinkController::class, 'stats'])->name('links.stats');
    Route::post('/links/shorten', [LinkController::class, 'shorten'])->name('links.shorten');
    Route::apiResource('links', LinkController::class);
});
\end{lstlisting}

\par Berdasarkan Kode \ref{lst:routes-api}, registrasi \textit{route} melalui perintah\\
\texttt{Route::apiResource('links', LinkController::class)} secara otomatis mendaftarkan lima operasi standar CRUD tanpa menyertakan \textit{route} formulir HTML (\texttt{create} dan \texttt{edit}), yaitu:
\begin{itemize}[leftmargin=*]
  \item \texttt{GET /api/links}: Mengambil seluruh koleksi data tautan aktif dan nonaktif dalam format JSON.
  \item \texttt{POST /api/links}: Menyimpan entitas tautan baru ke basis data dengan validasi masukan.
  \item \texttt{GET /api/links/\{id\}}: Mengambil rincian data satu entitas tautan spesifik.
  \item \texttt{PUT/PATCH /api/links/\{id\}}: Memperbarui data entitas tautan yang telah ada.
  \item \texttt{DELETE /api/links/\{id\}}: Menghapus data entitas tautan dari basis data.
\end{itemize}

\par Selain itu, disediakan \textit{route} pendukung \texttt{GET /api/links/stats/count} untuk rekapitulasi jumlah tautan aktif serta total tautan, dan \texttt{POST /api/links/shorten} untuk pemendekan instan. Pada sisi \textit{controller}, kelas \\
\texttt{LinkController} memanfaatkan \texttt{LinkResource} guna memastikan struktur \textit{payload} JSON konsisten serta terisolasi dari tabel internal, seperti disajikan pada Kode \ref{lst:link-controller-api}.

\begin{lstlisting}[language=php, caption={[Controller API \texttt{LinkController.php}]{Implementasi Controller API pada \texttt{app/Http/Controllers/Api/LinkController.php}}}, label={lst:link-controller-api}]
namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Http\Requests\Api\StoreLinkRequest;
use App\Http\Requests\Api\UpdateLinkRequest;
use App\Http\Resources\ApiResource;
use App\Http\Resources\ApiResourceCollection;
use App\Http\Resources\LinkResource;
use App\Models\Link;
use Illuminate\Http\JsonResponse;

class LinkController extends Controller
{
    public function index(): JsonResponse
    {
        $links = Link::latest()->get();
        return (new ApiResourceCollection(
            LinkResource::collection($links),
            'Berhasil mengambil daftar tautan'
        ))->response();
    }

    public function store(StoreLinkRequest $request): JsonResponse
    {
        $link = Link::create($request->validated());
        return (new ApiResource($link, 'Tautan berhasil ditambahkan', 201))
            ->response()
            ->setStatusCode(201);
    }
}
\end{lstlisting}

\par Berdasarkan Kode \ref{lst:link-controller-api}, seluruh respon dibungkus dalam format JSON terstandarisasi yang memuat atribut status, pesan konfirmasi, serta data \textit{payload}. Pola ini memudahkan lapisan klien dalam memproses hasil respon maupun mendeteksi galat secara seragam.

\subsubsection{Pengelolaan Kebijakan Cross-Origin Resource Sharing (CORS)}
\par Ketika aplikasi web antarmuka pengguna dijalankan pada server pengembangan Vite (berjalan pada alamat \texttt{http://localhost:5173}) dan mencoba melakukan permintaan data ke server Laravel (berjalan pada alamat \texttt{http://localhost:8000}), peramban web secara otomatis menerapkan mekanisme pengamanan \textit{Same-Origin Policy} (SOP). Perbedaan nomor \textit{port} antara \textit{origin} pemanggil dan tujuan permintaan mengharuskan server tujuan mengizinkan \textit{Cross-Origin Resource Sharing} (CORS).

\par Pada kerangka kerja Laravel 11, mekanisme penanganan CORS ditangani secara bawaan oleh \textit{middleware} \texttt{HandleCors} (\texttt{Illuminate\textbackslash Http\textbackslash Middleware\textbackslash HandleCors}) yang terpasang pada tumpukan \textit{middleware} global aplikasi pada penanganan permintaan berkas \texttt{bootstrap/app.php}. Ketika permintaan HTTP metode \texttt{OPTIONS} (\textit{preflight request}) atau permintaan HTTP biasa dikirim oleh klien Vue, \textit{middleware} ini secara otomatis menyertakan tajuk respon keamanan:
\begin{itemize}[leftmargin=*]
  \item \textbf{\texttt{Access-Control-Allow-Origin}}: Mengizinkan domain asal klien (\texttt{http://localhost:5173}) untuk mengakses sumber daya data.
  \item \textbf{\texttt{Access-Control-Allow-Methods}}: Mengizinkan metode HTTP yang digunakan mencakup \texttt{GET, POST, PUT, PATCH, DELETE, OPTIONS}.
  \item \textbf{\texttt{Access-Control-Allow-Headers}}: Mengizinkan tajuk kustom\\
        seperti \texttt{Content-Type}, \texttt{Accept}, dan \texttt{Authorization}.
\end{itemize}
Konfigurasi ini memastikan aplikasi antarmuka Vue 3 pada komputer lokal dapat berinteraksi dengan API Laravel secara mulus tanpa terblokir oleh kendala CORS.

\subsubsection{Konfigurasi Variabel Lingkungan API}
\par Sesuai batasan penugasan, alamat URL server API tidak boleh di-\textit{hardcode} di dalam kode program, melainkan wajib diambil secara dinamis dari variabel lingkungan \texttt{VITE\_API\_URL}. Hal ini diterapkan dengan menyediakan berkas percontohan lingkungan \texttt{frontend/.env.example} dan modul pembacaan pada \texttt{frontend/src/services/api.ts} seperti ditunjukkan pada Kode \ref{lst:env-service-api}.

\begin{lstlisting}[language=JavaScript, caption={[Pembacaan Environment API]{Pembacaan Variabel Lingkungan API pada \texttt{frontend/src/services/api.ts}}}, label={lst:env-service-api}]
export function getBaseApiUrl(): string {
  // Mengambil URL API secara dinamis dari variabel lingkungan Vite
  const envUrl = import.meta.env.VITE_API_URL
  if (!envUrl) {
    // Nilai fallback yang aman untuk lingkungan pengembangan lokal
    return 'http://localhost:8000/api'
  }
  return envUrl.replace(/\/+$/, '')
}
\end{lstlisting}

\par Berdasarkan Kode \ref{lst:env-service-api}, fungsi \texttt{getBaseApiUrl()} bertugas membaca konfigurasi lingkungan\\
\texttt{import.meta.env.VITE\_API\_URL} yang disediakan oleh mesin Vite saat proses kompilasi maupun saat server pengembang dijalankan. Apabila variabel lingkungan tidak terdefinisi (misalnya saat proses pengujian lokal mandiri), fungsi secara cerdas menyediakan mekanisme \textit{fallback} terstandarisasi pada alamat\\
\texttt{http://localhost:8000/api}. Dengan demikian, aplikasi dapat dengan mudah diarahkan ke alamat server \textit{staging} maupun \textit{production} yang berbeda hanya dengan mengubah konfigurasi lingkungan tanpa menyentuh kode sumber.

\subsubsection{Perancangan Navigasi Antarmuka Multi-Halaman}
\par Aplikasi antarmuka pengguna dilengkapi dengan modul manajemen \textit{routing} Vue Router pada berkas \\
\texttt{frontend/src/router/index.ts}. Konfigurasi \textit{routing} disajikan pada Kode \ref{lst:vue-router}.

\begin{lstlisting}[language=JavaScript, caption={[Konfigurasi Routing]{Konfigurasi Routing pada \texttt{frontend/src/router/index.ts}}}, label={lst:vue-router}]
import { createRouter, createWebHistory } from 'vue-router'
import LinksView from '../views/LinksView.vue'
import QuickShortenView from '../views/QuickShortenView.vue'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      name: 'links',
      component: LinksView,
    },
    {
      path: '/quick-shorten',
      name: 'quick-shorten',
      component: QuickShortenView,
    },
    {
      path: '/links',
      redirect: '/',
    },
  ],
})

export default router
\end{lstlisting}

\subsection{Perancangan Pipeline CI/CD Empat Job Frontend pada GitHub Actions}

\par Menjawab butir penugasan ketiga, keempat, dan kelima, repositori dilengkapi dengan konfigurasi pipeline otomasi yang didedikasikan untuk modul antarmuka pengguna pada berkas \texttt{.github/workflows/frontend.yml}. Pipeline ini mengatur \textit{Continuous Integration} (CI) dan \textit{Continuous Delivery} (CD) dengan arsitektur multi-tahap yang aman dan efisien.

\subsubsection{Struktur dan Ketergantungan Antar-Job}
\par Berkas \textit{workflow} otomasi merangkai empat \textit{job} terpisah menggunakan direktif dependensi \texttt{needs:}. Seluruh definisi konfigurasi disajikan secara lengkap pada Kode \ref{lst:workflow-frontend}.

\begin{lstlisting}[language=yaml, caption={[Pipeline Frontend CI/CD]{Konfigurasi Pipeline Frontend CI/CD (\texttt{.github/workflows/frontend.yml})}}, label={lst:workflow-frontend}]
name: Frontend CI/CD Pipeline

on:
  push:
    branches: ['main', 'dev', 'feature/**', 'chore/**']
  pull_request:
    branches: ['main']

jobs:
  lint:
    name: Lint
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository

    name: Build Frontend
    needs: [test]
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

        uses: actions/setup-node@v4

\par Berdasarkan Kode \ref{lst:workflow-frontend}, arsitektur \textit{workflow} dibangun atas prinsip-prinsip rekayasa otomasi penting:
\begin{enumerate}[label=\arabic*.]
  \item \textbf{Penggunaan \texttt{npm ci} dan Mekanisme Caching Dependensi}: Seluruh \textit{job} mengeksekusi instalasi paket dependensi menggunakan perintah \texttt{npm ci} di dalam direktori kerja \texttt{frontend}. Berbeda dengan \texttt{npm install}, perintah \texttt{npm ci} membaca berkas pengunci \texttt{package-lock.json} secara kaku sehingga menjamin integritas dependensi yang identik (\textit{deterministic build}) di lingkungan \textit{runner}. Efisiensi dipercepat dengan konfigurasi \texttt{cache: 'npm'} dan parameter\\
        \texttt{cache-dependency-path} pada aksi \texttt{actions/setup-node@v4}, menghindari pengunduhan ulang paket biner dari \textit{registry} luar pada eksekusi berulang.
  \item \textbf{Rantai Ketergantungan \texttt{needs:}}: Tahapan eksekusi disusun secara sekuensial hierarkis:
        \begin{center}
          \texttt{lint} $\longrightarrow$ \texttt{test (needs: [lint])} $\longrightarrow$ \\
          \texttt{build (needs: [test])} $\longrightarrow$ \texttt{deploy (needs: [build])}
        \end{center}
        Struktur ini memastikan bahwa kode yang tidak lolos standar gaya penulisan atau mengandung galat pengujian unit akan langsung dihentikan secara \textit{fail-fast} sebelum proses kompilasi aset statis yang memakan sumber daya komputasi dijalankan.
\end{enumerate}

\subsubsection{Mekanisme Transfer Artefak Tanpa Re-Build (Zero Build on Deploy)}
\par Memenuhi butir penugasan keempat, \textit{job} \texttt{deploy} tidak diperbolehkan menjalankan ulang perintah \texttt{npm run build}. Sebagai gantinya, hasil kompilasi dari \textit{job} \texttt{build} dioper secara utuh menggunakan mekanisme \textit{artifact sharing} GitHub Actions:
\begin{itemize}[leftmargin=*]
  \item Pada \textit{job} \texttt{build}, aksi \texttt{actions/upload-artifact@v4} mengompresi dan mengunggah seluruh isi direktori rilis \texttt{frontend/dist/} ke penyimpanan artefak terkelola GitHub dengan nama \texttt{frontend-dist}.
  \item Pada \textit{job} \texttt{deploy}, aksi \texttt{actions/download-artifact@v4} mengambil artefak \texttt{frontend-dist} tersebut dan mengekstraknya kembali ke direktori \texttt{frontend/dist}.
  \item \textit{Step} selanjutnya mengeksekusi perintah terminal \texttt{ls -la frontend/dist} serta perintah \\
        \texttt{find frontend/dist -type f} untuk menampilkan seluruh struktur berkas rilis ke log eksekusi, memverifikasi ketersediaan berkas \texttt{index.html}, aset JavaScript terkompilasi, serta lembar gaya CSS.
\end{itemize}
Mekanisme ini mencerminkan praktik terbaik industri (\textit{Twelve-Factor App}) di mana tahapan \textit{build} dipisahkan secara tegas dari tahapan \textit{deploy}, menjamin bahwa artefak yang diuji di lingkungan simulasi persis sama dengan artefak yang dirilis ke server produksi.

\subsubsection{Aturan Proteksi Lingkungan dan Pembatasan Deploy pada Branch Main}
\par Memenuhi butir penugasan kelima, pengamanan eksekusi diterapkan pada tingkat deklarasi \textit{job} \texttt{deploy} dengan menyertakan ekspresi kondisi:
\begin{center}
  \texttt{if: github.ref == 'refs/heads/main' \&\& github.event\_name != 'pull\_request'}
\end{center}
\par Aturan logika ini memberikan dua tingkat perlindungan:
\begin{itemize}[leftmargin=*]
  \item Apabila terjadi aktivitas \textit{push} pada \textit{branch} fitur (seperti \texttt{feature/vue}), \textit{branch} perbaikan (\texttt{chore/**}), atau \textit{branch} pengembangan (\texttt{dev}), \textit{workflow} tetap menjalankan \textit{job} \texttt{lint}, \texttt{test}, dan \texttt{build} secara lengkap guna memvalidasi kelayakan kode, namun \textit{job} \texttt{deploy} secara otomatis berstatus \textit{skipped}.
  \item Apabila dibuat suatu \textit{Pull Request} (PR) yang menargetkan \textit{branch} \texttt{main}, \textit{workflow} bertindak sebagai \textit{quality gate} dengan menjalankan pemeriksaan kualitas kode dan pengujian unit tanpa memicu proses \textit{deployment}.
  \item \textit{Job} \texttt{deploy} hanya dan hanya akan dieksekusi ketika perubahan telah disetujui dan di-\textit{merge} ke dalam \textit{branch} utama \texttt{main}.
\end{itemize}

\begin{lstlisting}[language=JavaScript, caption={[Utilitas Logika Mandiri]{Fungsi Utilitas Logika Mandiri pada \texttt{frontend/src/utils/linkLogic.ts}}}, label={lst:link-logic-utils}]
export function isValidUrl(url: string): boolean {
  if (!url || typeof url !== 'string') return false
  const trimmed = url.trim()
  try {
    const parsed = new URL(trimmed)
    return parsed.protocol === 'http:' || parsed.protocol === 'https:'
  } catch {
    return false
  }
}

export function isValidAlias(alias: string): boolean {
  if (!alias) return true // alias bersifat opsional
  const regex = /^[a-zA-Z0-9_-]+$/
  return regex.test(alias.trim())
}

export function buildApiUrl(
  base: string,
  endpoint: string,
  params?: Record<string, string | undefined>
): string {
  const cleanBase = (base || '').replace(/\/+$/, '')
  const cleanEndpoint = (endpoint || '').replace(/^\/+|\/+$/g, '')
  const fullUrl = cleanEndpoint ? `${cleanBase}/${cleanEndpoint}` : cleanBase

  if (!params) return fullUrl

  const searchParams = new URLSearchParams()
  for (const [key, value] of Object.entries(params)) {
    if (value !== undefined && value !== null && value !== '') {
      searchParams.append(key, value)
    }
  }

  const queryString = searchParams.toString()
  return queryString ? `${fullUrl}?${queryString}` : fullUrl
}

export function calculateStats(links: LinkItem[]): LinkStats {
  const safeLinks = Array.isArray(links) ? links : []
  const activeCount = safeLinks.filter((item) => item && item.is_active === true).length

  return {
    active_links_count: activeCount,
    total_links_count: safeLinks.length,
  }
}
\end{lstlisting}

\section{Kesimpulan}

\par Berdasarkan seluruh tahapan praktikum Konstruksi dan Evolusi Perangkat Lunak Tugas \Pertemuan\ mengenai integrasi aplikasi antarmuka pengguna Vue 3 dengan backend Laravel REST API serta perancangan pipeline CI/CD multi-job pada repositori \texttt{evolusi-pl-24-538699-SV-24524}, dapat disimpulkan beberapa poin penting sebagai berikut:
\begin{enumerate}[leftmargin=*]
  \item \textbf{Integrasi Arsitektur RESTful API dan Penanganan CORS}: \\
        Penyediaan \textit{endpoint} JSON melalui \texttt{Route::apiResource} dan \textit{controller} \texttt{LinkController} pada \textit{backend} Laravel 11 berhasil menyajikan operasi CRUD terstandarisasi untuk modul URL Shortener. Mekanisme \textit{middleware} \texttt{HandleCors} secara efektif mengatasi batasan \textit{Same-Origin Policy} sehingga aplikasi antarmuka Vue 3 pada lingkungan lokal laptop dapat bertukar data tanpa hambatan.
  \item \textbf{Arsitektur Antarmuka Vue 3 Berbasis Lingkungan Dinamis}: \\
        Aplikasi antarmuka pengguna berhasil dibangun dengan Vue 3 dan Vite, memfasilitasi navigasi multi-halaman ber-router (\texttt{LinksView} dan \texttt{QuickShortenView}). Konfigurasi alamat API berhasil diabstraksikan melalui variabel lingkungan \texttt{VITE\_API\_URL} dengan mekanisme \textit{fallback} yang aman, mencegah penulisan URL statis secara langsung pada kode sumber.
  \item \textbf{Orkestrasi Pipeline Empat Job dan Efisiensi Caching}: \\
        Pipeline frontend CI/CD pada GitHub Actions berhasil mengorkestrasi empat tahapan kerja (\textbf{Lint} $\rightarrow$ \textbf{Unit Test} $\rightarrow$ \textbf{Build} $\rightarrow$ \textbf{Deploy}) menggunakan direktif ketergantungan \texttt{needs:}. Penggunaan instalasi\\
        \texttt{npm ci} yang dipadukan dengan opsi \texttt{cache: 'npm'} secara terukur memangkas durasi pengunduhan dependensi di lingkungan runner.
  \item \textbf{Pemisahan Artefak Rilis Tanpa Re-Build}: \\
        Penerapan mekanisme transfer artefak melalui kombinasi aksi rilis\\
        \texttt{upload-artifact} dan \texttt{download-artifact} membuktikan pemenuhan prinsip \textit{build once, deploy anywhere}. \textit{Job} deploy berhasil memverifikasi dan menyebarkan aset direktori \texttt{dist/} ke log tanpa melakukan kompilasi ulang yang redundan.
  \item \textbf{Keandalan Unit Test Mandiri dan Ketahanan Quality Gate}: \\
        Pemisahan logika murni ke dalam modul \texttt{linkLogic.ts} memungkinkan 19 kasus pengujian Vitest dieksekusi secara terisolasi tanpa memerlukan dependensi server backend. Sistem otomasi terbukti tangguh sebagai \textit{quality gate}: mampu mendeteksi kegagalan (status \textit{failed}) saat terjadi ketidaksesuaian lingkungan, segera pulih sukses (\textit{passed}) setelah tindakan korektif diterapkan, serta secara andal membatasi hak akses \textit{deployment} hanya untuk \textit{branch} utama \texttt{main}.
\end{enumerate}
